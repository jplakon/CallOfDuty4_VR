# Installing KisakCOD VR

## Before you start

You need the original 2007 Windows version of Call of Duty 4: Modern Warfare.
The remastered game is not a substitute. The KisakCOD VR package includes
the matching 32-bit Steamworks, Bink, and Miles runtime files required by the
rebuilt executable, but it does not contain COD4 maps, fastfiles, saves, or
other Call of Duty game data.

This beta is tested primarily with:

- Meta Quest 3
- Virtual Desktop using VDXR, its OpenXR runtime
- NVIDIA RTX 3080 Ti

For Quest headsets, VDXR is the recommended and known-working runtime. Meta
Quest Link's 32-bit OpenXR runtime can crash inside `xrCreateSession` on
affected systems. Other headset and runtime configurations may work but are
experimental.

## Installation

1. Install COD4 through Steam and launch its single-player mode once.
2. In the Steam library, right-click the game.
3. Choose **Manage → Browse local files**.
4. Confirm that the opened folder contains `iw3sp.exe` and a `main` folder.
5. Extract every file from the KisakCOD VR ZIP directly into this folder.
6. Start the intended runtime. Quest users should use Virtual Desktop with
   VDXR; the SteamVR/OpenVR backend supports controller input but remains an
   experimental compatibility path.
7. Double-click `Launch-KisakCOD-VR.bat`.

The mod executable must remain beside `iw3sp.exe`. Do not replace or rename
`iw3sp.exe`.

## Adjusting VR settings

Run `KisakCOD-VR-Configurator.exe` from the COD4 folder. For the first launch,
open **Setup & Compatibility** and click **Rescan system**. Resolve every
Blocked item. Review the exact backend/graphics delta before choosing **Apply
recommended**; the action never changes handedness, units, comfort, controls,
HUD, height, interaction, or weapon/gunstock calibration. Then save and launch.
The other built-in presets are Performance, Comfort Snap, Smooth Turn, Seated,
and Minimal HUD; every setting can also be customized individually.

The configurator covers:

- unified installation, DirectX, GPU, 32/64-bit OpenXR, OpenVR, and prior live
  headset/controller compatibility checks with an exportable support report
- snap angle, smooth-turn speed, movement direction, and stick deadzones
- native/performance rendering, FSR, brightness, shadows, and scope quality
- a visual HUD canvas for ammo/equipment, compass/objective icons, normal
  notifications, bold objective/status banners, and subtitles
- dominant-hand selection plus weapon-hand/off-hand fit and tracking response
- per-weapon hip/shouldered overrides and shareable physical-gunstock profiles
- physical-pull or button reload, belt/grenade layout, grip modes, physical
  melee, haptics, muzzle obstruction, and two-hand strength
- physical-scope alignment and controller-neutral action bindings
- separate position-only, direction/level-only, and full live recentering plus
  standing and seated eye-height calibration
- Metric or Imperial presentation for all physical calibration values

It validates the selected combination, offers live previews, and can launch the
normal or one-run diagnostic mode. A beta.13 save is successful only after all 142
settings, the weapon-profile document, and the exact generated bytes read back
from disk. Personal settings
are written to:

```text
%LOCALAPPDATA%\KisakCOD-VR\VR-User-Settings.bat
```

The previous profile is backed up on every save. Import and Export can move a
profile between installations. If upgrading from an earlier beta with a
hand-edited `VR-Settings.bat`, keep a copy and import it after installing.
Most setting changes require COD4 to be fully closed and restarted. The
**Height & Recenter** page is one exception: its recenter and height buttons
can safely update a running single-player game. **Edit live in headset** on the
HUD page is the other; it moves and resizes the running mission HUD directly.

Each setup scan and every launcher preflight atomically writes:

```text
%LOCALAPPDATA%\KisakCOD-VR\Compatibility-Report.txt
```

Offline checks can prove files and runtime registration but cannot prove that a
headset is awake or that the runtime will create a graphics session. Run **Save
& Launch Diagnostics** once, then rescan. A successful runtime appends its
actual backend, runtime, headset/system, and controller profiles to the active
settings receipt for the next compatibility scan.

Each saved profile has a visible revision. On launch, the batch file validates
the selected override and writes the effective environment to:

```text
%LOCALAPPDATA%\KisakCOD-VR\Active-VR-Settings.txt
```

The game appends `STATUS=RUNTIME_ACCEPTED` plus its parsed weapon-offset and
manual-interaction values. Beta.13 also appends the dominant hand and accepted
physical-interaction policy, plus the selected display units, active
calibrated height, and receipts for live recenter, height, HUD, weapon-profile,
and guided-aim-capture requests.
These receipts and the matching `[VR][CONFIG]` / `[VR][CALIBRATION]` lines in
`main\console.log`
identify the exact settings revision and calibration used by the game.

### Visual HUD editor

Open **HUD & Text** and choose **Open desktop visual editor**. The 640x480
canvas shows the tested safe area, snap anchors, the optical-center crosshair,
and five colored HUD groups. Drag a group to move it. Drag its yellow resize
corner, use the mouse wheel, or use the arrow keys to refine it. Hold Shift
while dragging to bypass snapping. Previous / Next or Shift+Tab / Tab selects
a group without clicking its rectangle; **Center selected element** or Home
recovers it to the canvas center, and **Reset selected element** or End restores
only that group. **Apply layout** writes the result back to the configurator;
click **Save** to persist it.

For an exact mission-context check, launch COD4, enter a mission, and choose
**Edit live in headset**. Point the weapon controller at a group and hold its
trigger to drag it. Weapon-hand stick up/down resizes the selected group,
off-hand grip temporarily disables snapping, the primary action saves, and the
secondary action cancels. Use / Next weapon selects the previous / next group
(Quest X / Y), Sprint centers it (Quest left-stick click), and Melee resets
only it (Quest right-stick click). Shift+Tab / Tab, Home, and End provide the
same keyboard operations. The fixed selected-group banner remains visible even
if the group itself is off-screen. Gameplay input is suppressed while the
editor is open. Saving imports the live layout into the configurator and
performs the same 142-value disk verification automatically. Cancel restores
the complete entry layout. The crosshair is intentionally locked to the
optical center and is not a movable group.

### Per-weapon and gunstock calibration

Set a conservative global fit first on **Weapons & Hands**, then choose **Open
calibration editor**. With COD4 in an active mission, **Use equipped weapon**
adds the current stable internal weapon id. Each weapon has a hip-fire delta
and a shouldered/ADS delta. The active gunstock has one shouldered correction
shared across weapons. All six values are additive to the global baseline;
the shouldered layers blend smoothly with ADS or the physical two-hand grip.

**Apply live** atomically saves the profile and asks the running game to reload
it. **Guided aim capture** is available on the gunstock and per-weapon
shouldered layers. It captures only the current absolute rotation after a
five-second shoulder-and-aim countdown; Forward/Left/Up remain manual for
precise physical-stock placement. No automatic startup pose is saved as a
neutral orientation.

The collection is stored at:

```text
%LOCALAPPDATA%\KisakCOD-VR\VR-Weapon-Profiles.ini
```

Use `.vrstock` Import/Export to move one physical-stock profile between PCs.
Deleting a weapon override immediately falls back to the global baseline.

### Guided recenter and player height

Open the configurator's **Height & Recenter** page. Use **Recenter position
only** when your physical location has drifted but your angles are already
correct. Use **Recenter direction / level only** when the forward or level
baseline needs correction but your positional origin is already correct. Use
**Full recenter** only when both should change. None of these actions changes
the OpenXR or SteamVR system origin.

The **First-gameplay recenter** selector offers Off, Position only, Direction /
level only, and Full. Full preserves the legacy combined default. Existing profiles
that stored the old `0` or `1` toggle are migrated to Off or Full automatically.

For standing play, stand normally and choose **Measure standing height**. The configurator
uses the runtime's floor reference when one is available and accepts only a
plausible 106.7-213.4 cm eye height in Metric mode (42-84 in in Imperial mode).
If no floor reference is available, set the height manually with the 1 cm or
1 in buttons selected by **Measurement units**. For seated play, sit naturally
and choose **Apply seated + recenter position**; the saved seated height can be
tuned the same way without changing direction/level. Standing measurement also
leaves both recenter components unchanged. The native 152.4 cm / 60 in setting
preserves the beta.7 view scale.

When COD4 is running, these actions are applied live after a short countdown.
When it is closed, the selected mode and height are still saved for the next
launch; start the game and press the desired action again to capture a new
forward pose or floor measurement.

During VR gameplay, common COD4 prompts now display the configured controller
binding instead of the corresponding PC key. The shared resolver covers both
normal HUD prompts and single-player script key lookups, shows primary and
alternate VR slots when available, and preserves the original keyboard label
for unknown or unbound actions. Full-screen keyboard menus intentionally remain
keyboard-labeled. See `CONTROLS.md` for the exact text-label policy.

On the **Controls** page, every gameplay and menu action has a primary and
optional alternate binding. Choose a compatible input from either controller,
or click **Bind...** and physically use the control. Press-to-bind starts a
brief black VR capture session, so close COD4 and start the configured runtime
first. Beta.7 values such as `x`, `y`, `a`, `b`, and `stick` are migrated to
controller-neutral equivalents when an older profile is imported.

The verified Quest render pairs remain `6016x2688` with output scale `1.00`
(Native) and `4768x2016` with output scale `0.75` (Performance). Beta.13 also
adds the Pimax Crystal Light `7684x3128` packed mode: two `3330x3128` eyes plus
the 1024-pixel scope panel. Real Pimax hardware confirmation is still pending.
Do not use `3072x1536`; it cannot contain both eyes and the dedicated scope
panel.

### Runtime backend

The default setting is:

```bat
set "KISAK_VR_BACKEND=auto"
```

Available values are:

- `auto` keeps the normal behavior: OpenXR remains primary, with the
  experimental 32-bit SteamVR/OpenVR client used only when no compatible
  32-bit OpenXR runtime can be enumerated.
- `openxr` forces OpenXR. Use this with Virtual Desktop's VDXR or Pimax
  OpenXR.
- `openvr` forces the experimental 32-bit SteamVR/OpenVR compatibility path.
  It provides headset and controller tracking plus the same configured action
  model through SteamVR's legacy controller API. Driver-specific button aliases
  may require remapping.

Changing this setting does not make SteamVR a 32-bit OpenXR runtime. Fully
close and restart COD4 after changing it.

HUD, compass, game-text, weapon/hand, belt, and physical-scope controls are
exposed by the configurator. Physical values are shown in cm or cm/s in Metric
mode and in or in/s in Imperial mode. Advanced users may still inspect the
generated batch profile; its game-compatible canonical values intentionally
retain the beta.8 inches and meters schema.

## Normal and diagnostic launchers

- `Launch-KisakCOD-VR.bat` hides development warnings from the headset while
  retaining a log.
- `Launch-KisakCOD-VR-Diagnostics.bat` enables developer messages when a bug
  must be investigated.

Logs are normally written below the game directory in:

```text
main\console.log
```


## Crash reports

If the game crashes, do not reopen it. Run
`Collect-KisakCOD-VR-Crash-Report.bat` from the COD4 folder and send the ZIP
created on the Windows Desktop privately. A minidump can contain limited
process memory and should not be posted publicly.

## Known campaign limitation

Every standard campaign mission is unlocked in Mission Select at startup,
including on a new profile. Developer mode remains disabled.

**Death From Above is not supported in beta.13, even though it
appears unlocked.**

To skip **Death From Above**:

1. From the main menu, open **Options -> Game Options** and set
   **Enable Console** to **Yes**.
2. Press `~` to open the console. If necessary, use `Shift+~`.
3. Enter `/spmap bog_b` and press Enter.
4. This loads **War Pig**, the mission immediately following
   **Death From Above**.

Loading `bog_b` directly does not mark Death From Above as completed in the
original profile. If the campaign menu later returns to the unsupported
mission, repeat `/spmap bog_b`.

## Common problems

### The launcher says it is in the wrong folder

Move the extracted files beside `iw3sp.exe`. Do not run the launcher from a
Downloads subfolder.

### A required DLL is missing

Confirm that `steam_api.dll`, `binkw32.dll`, and `mss32.dll` were extracted
beside `KisakCOD-sp.exe`, and that the package's `miles` folder was merged into
the game's `miles` folder. Do not download individual DLLs from third-party
sites. For a missing DirectX DLL, install Microsoft's official legacy DirectX
runtime.

### The game opens but no image appears in the headset

With `auto` or `openxr`, start the intended OpenXR runtime first and make it the
active system OpenXR runtime. With `openvr`, start SteamVR and connect the
headset before launching the mod. Then restart both the runtime and the game.

### Meta Quest Link crashes during OpenXR startup

Meta's 32-bit OpenXR runtime can crash inside `xrCreateSession` after the mod
has successfully created its D3D11 device. Because the runtime terminates the
process instead of returning an OpenXR error, `KISAK_VR_BACKEND=auto` cannot
continue to the OpenVR fallback.

For Quest headsets, use Virtual Desktop with VDXR. To select VDXR only for
KisakCOD VR without changing the system-wide OpenXR runtime, add this to
`VR-Settings.bat` using Virtual Desktop's default installation path:

```bat
set "XR_RUNTIME_JSON=C:\Program Files\Virtual Desktop Streamer\OpenXR\virtualdesktop-openxr-32.json"
```

Leave `KISAK_VR_BACKEND=auto` selected. Fully close COD4 and restart it through
`Launch-KisakCOD-VR.bat`.

### Performance is poor

Edit `VR-Settings.bat`, change `VR_CUSTOM_MODE` from `6016x2688` to
`4768x2016`, change `KISAK_VR_OUTPUT_SCALE` from `1.0` to `0.75`, save, and
fully restart the game. Shadows can also be disabled by changing:

```bat
set "KISAK_VR_SHADOWS=1"
```

to:

```bat
set "KISAK_VR_SHADOWS=0"
```

### The scope or HUD is misplaced

Use the configurator's visual HUD editor for HUD groups. Use the scope controls
for physical-scope alignment. Raw numeric values remain available in Advanced
mode for diagnosis.
